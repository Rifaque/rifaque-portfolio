Windows to Android second screen · case study

ExtendSpace

A Windows host and an Android companion that stream the desktop to a tablet over USB. The wired path is the first milestone and the current focus; ordinary use is not possible yet, because Connect is still disabled.

The aim, and the order of work

Can a tablet on a USB cable become a dependable second screen for Windows?

Mirroring first, true extension later; extension needs a virtual display driver on Windows. The work so far is the streaming pipeline and the session machinery around it.

  • First: USB, wired. The current focus is finishing this path.
  • Then: Wi-Fi, wireless. Planned after the wired milestone, when development resumes. It is not implemented.

How it is put together

  • Windows host in C# and WinUI 3: display capture and hardware H.264 encoding behind a production session owner.
  • Android companion in Kotlin and Jetpack Compose: link, decoder ownership and surface handling, with a session state model covered by unit tests.
  • A draft wire protocol, implemented on both sides, over a USB transport with reconnection.

The host screen in the 3D view is an illustration: no capture of the host interface is published.

What has been tested

On one PC and one tablet over USB, the production session path streamed a 1080p60 test pattern for ten minutes: 36,081 frames sent, all decoded and released to the tablet's surface.

These runs were driven by gated acceptance tests on the PC and a debug-only screen on the tablet. They show the pipeline working on one setup; they are not broad device validation.

Recovering, not restarting

The USB link recovers from a pulled cable with video still flowing afterwards.

Decoders are created on a dedicated owner thread, never on the reader thread, and a creation is used only if it still matches the stream that is wanted. Frames that arrive meanwhile wait in order, within limits; beyond that, the stream skips to the next keyframe.

Status and limits

  • Connect is disabled in both apps, and each says so in its own interface.
  • Wi-Fi is planned after the wired milestone. Pairing and input forwarding do not exist yet.
  • The virtual display driver for extension is not implemented; only its feasibility has been researched.
  • Tested on one PC and one tablet only.
